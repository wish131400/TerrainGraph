# TerrainGraph 0.1.3

适用版本：Minecraft 1.20.1、Forge 47.x、Java 17 或以上。
这是一个独立的区块生成优化模组

## 安装

将 `terraingraph-1.20.1-forge-0.1.3.jar` 放入服务端 `mods` 文件夹，替换旧版后重启即可。
客户端连接专用服务器时不需要安装。单人游戏可安装在客户端，由内置服务器使用。
首次启动会生成 `config/terraingraph-common.toml`，正常使用保持默认配置。
此文件不支持其他 Minecraft 版本、Fabric 或 NeoForge。

## 优化的位置

结构模组为了判断地形高度，会频繁创建噪声计算上下文；每次初始化又会重复转换共享的计算子图。
TerrainGraph 在一次初始化内复用已转换的同一个节点，减少重复遍历、临时对象和哈希比较。
第二次最终密度图转换复用支持原版入口，以及 ByePregen 1.1.2.4 的已验证入口。
0.1.3 在未安装 ByePregen 或关闭其 DFC 时，也可通过原版入口使用第二次优化。
两次转换各自使用独立缓存。

缓存限定在一次转换内，不跨线程、区块、维度或世界共享计算上下文。
首次转换仍使用原来的实现；原有节点包装与结构相等判断继续执行。
模组不改地形公式、结构生成条件、网络协议或传送命令，不会在世界存档中写入额外缓存。

## 兼容性

转换 visitor 带有额外接口时保留原对象，跳过该次转换复用，避免遮住其他模组的接口标记。
C2ME DFC 使用的地形混合标记属于这种情况；这项保护不需要依赖 C2ME，也不会关闭 C2ME。
如果其他模组在外层包装了 TerrainGraph 的 visitor，缓存入口不会把该外层对象识别为 TerrainGraph visitor。

模组会在所有 mixin 应用后检查第二次转换的实际入口：

- 原版 `cacheAllInCell(...).mapAll(this::wrap)` 调用仍存在时，通过原版入口接入；不要求安装 ByePregen。
- ByePregen 1.1.2.4 接管调用时，检查注入来源、方法签名、构造调用和转换入口，再包装原有 visitor。
- 遇到未知重定向、其他 visitor 注入、原节点构造变化或多个有歧义的调用时，跳过第二次优化。

只接入一个入口，不会重复包装。ByePregen 的校验根、插值器捕获和 DFC 绑定保留，
不需要修改或替换其 JAR。第二次优化跳过时，第一次转换优化仍可使用。
启动日志及 `/terraingraph stats` 会显示 `active: vanilla` 或 `active: ByePregen 1.1.2.4` 等接入状态。

已检查当前 ByePregen、ModernFix、ZFastNoise 等整合包组合，以及 visitor 标记的保留。
尚未完成同版本 C2ME DFC 联用的启动、地形一致性和收益测试。
本 JAR 仍仅支持 Forge 1.20.1，不可安装到 NeoForge 1.21.1。

## 配置

```toml
enabled = true
reuseFinalDensity = true
maxNodesPerTraversal = 8192
collectMetrics = false
```

- `enabled`：是否启用优化，修改后重启。
- `reuseFinalDensity`：是否启用原版或受支持的 ByePregen 第二次转换复用。设为 `false` 可保留第一次转换优化，修改后重启。
- `maxNodesPerTraversal`：每次转换最多保存多少个原节点，默认 8192。达到上限后，新节点继续按原流程转换。
- `collectMetrics`：诊断统计，正常使用保持关闭。开启后可用 `/terraingraph stats` 查看当前进程的累计转换与复用次数，需要管理员权限。

统计中的 `traversals` 包含两次转换，`finalTraversals` 是第二次转换次数。
`finalSpecialVisitors` 是因特殊接口而跳过的第二次转换次数。
`reused` 与 `converted` 表示已接入节点的缓存命中及未命中次数，不是耗时、唯一节点数或所有自定义节点的总量。

排查时可使用启动参数 `-Dterraingraph.disabled=true` 强制关闭转换复用，或移除 JAR 后重启。

## 已测收益

0.1.3 已完成原版入口、关闭第二次优化以及 ByePregen DFC 开启和关闭的运行验证。
下方收益来自此前开启 ByePregen DFC 的环境，不代表未安装 ByePregen 时的提升幅度。

0.1.2 正式 JAR 使用原始 ByePregen 1.1.2.4 和 Zeta JAR 做了四轮对照，每轮请求 192 个完整区块。
与仅启用第一次转换优化相比，加入第二次转换后：

| 指标 | 仅第一次转换复用 | 两次转换复用 | 减少 |
| --- | ---: | ---: | ---: |
| 平均生成耗时 | 23.81 秒 | 17.37 秒 | 27.1% |
| 进程 CPU 用量 | 52.17 CPU 秒 | 36.19 CPU 秒 | 30.6% |
| 临时对象分配量 | 19.17 GB | 6.90 GB | 64.0% |

CPU 秒是所有线程占用 CPU 时间的总和，可能大于实际等待时间。
分配量是测试期间创建对象的累计大小，不是常驻内存或内存峰值。
结果仅对应本次整合包、种子、硬件和路线；不应与下方此前的传送收益直接相加。
完整生成在同配置的不同 JVM 之间也会出现差异，因此不能宣称所有模组生成结果完全相同。
这些数据只适用于测试用的整合包、种子、硬件和路线。

此前第一阶段优化的四轮冷传送对照中，每组 8 次请求，平均等待从 7.00 秒降到 4.02 秒，减少 42.5%。
生成线程 CPU 用量减少约 38.6%，累计临时对象分配的采样估计减少约 55.3%。
结果针对本次整合包、硬件、种子和四个目的地；不代表所有服务器都会有相同幅度的提升。
这个版本减少生成工作量，传送等待入口仍然同步，因此冷传送仍可能短暂停顿。

发布分支包含模组源码和构建文件；测试服务器、运行日志和基准数据保存在开发环境中，
没有放进发布源码树。
